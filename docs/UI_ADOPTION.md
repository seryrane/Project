## 1. 샘플별 강점 분석

### Figma 작업분 (HMG Admin) — 비주얼 톤과 핵심 화면 패턴이 우수

- **전체 Look & Feel**: 뉴트럴 팔레트(다크 사이드바 + 밝은 콘텐츠) + 절제된 포인트 컬러, 넉넉한 여백과 카드 그림자. "세련되고 트렌디" 요구에 3종 중 가장 부합 → **기준 톤으로 채택**
- **사양서 목록(카드형)**: 사양서 ID(SP-001) + 상태 배지(승인 대기/검토 중/배포 완료/초안) + 버전 칩(v2.3) + 카테고리/태그 + **핵심 스펙 미리보기 영역** + 담당자 아바타 + 수정일 + 액션(상세 보기/버전 비교/승인 요청)
- **버전 비교 모달**: 이전/현재 버전 좌우 대비, 변경 전 값은 빨강 배경+취소선, 변경 후 값은 초록 배경, 무변경 항목은 중립 표시, 하단 범례 → 우리 P1 "Diff 단위(행/컬럼/텍스트)" 요건의 실물 답안
- **수정 이력 탭**: 상세 모달 내 탭 구조(사양 항목 / 수정 이력 N / 편집) + 버전 타임라인(버전·상태·변경 요약·작성자·일자) + 각 이력에서 "현재 버전과 비교" 진입
- **메뉴 구조**: 승인 관리·배포 관리를 별도 메뉴로 분리하고 **뱃지 카운트**(승인 대기 7, 시스템 알림 3) 표시 — 결재자 동선에 유리

### 스카이워크 작업분 1 (AdminPortal) — 기능 커버리지(IA)와 편집 UX가 우수

- **LNB 정보 구조가 우리 요구사항과 가장 정합**: 메인(대시보드) / 관리(회원·권한·메뉴) / 사양(사양서관리) / 검증엔진(관리·검증 결과 조회·검증 리포트 3분할) / 보고·통계 / 커뮤니티(공지·Q&A·FAQ·사용자가이드) / 시스템(개인정보보호) — 검증엔진을 3개 화면으로 분리한 점이 검증 결과 리포팅 요건(P2)과 정확히 맞음
- **필드 일괄 편집(카드 그리드)**: 32개 필드를 카드로 동시 편집. 카테고리 탭 필터(기본정보 8/기술사양 10/운영정보 7/연계정보 4/보안·감사 3) + 필드명 검색 + 필드별 {타입, 최대길이, 상태, 설명, **유효성 규칙(정규식)**, 담당자} + 상단 진행 요약 배지(완료 16/진행중 5/검토중 4/미완료 7)
- **임시저장 vs 전체 저장 분리** + 목록 화면의 엑셀 업로드/버전 비교/이력/임시저장 버튼 배치
- 필드 단위 담당자·상태 추적 — 여러 담당자가 나눠 작성하는 사양서 협업 현실을 반영

### 스카이워크 작업분 2 (Data-Inside 통합 관리자 포털)

- Data-Inside 표준 Look & Feel 참고용 — 공통 포털(GNB/테마)이 사내 표준과 어떻게 붙는지의 레퍼런스로 활용

## 3. 채택으로 파생되는 표준 정의

**사양서 상태 흐름 (배지 체계)**

```
초안 → 검토 중 → 승인 대기 → 배포 완료
```

- 문서(사양서) 단위 상태: 위 4단계 (+반려 시 초안/검토 중 복귀 — Workflow 정책 확정 필요)
- 필드 단위 작성 상태: 미완료 → 진행중 → 검토중 → 완료 (협업 진척 추적용, 문서 상태와 별개)

**사양서 메타 구조 (샘플에서 역추출한 도메인 힌트)**

- 사양서 = ID(SP-xxx) + 명칭 + 카테고리(파워트레인/전동화/자율주행/차체·안전…) + 태그 + 버전 + 상태 + 담당자 + 수정일
- 필드 = 명칭(한/영) + 카테고리(기본정보/기술사양/운영정보/연계정보/보안·감사) + 타입(string/select…) + 최대길이 + 필수 여부 + 설명 + **유효성 규칙(정규식)** + 담당자 + 작성 상태
- 필드 레벨 정규식 유효성은 검증엔진의 "형식 검증" Rule과 연결 가능 — 사양서 필드 정의가 곧 1차 검증 Rule의 소스가 되는 구조 검토

**통합 LNB 초안**

```

─ 사양 (IDMS)

─ 검증엔진

```

※ KPI(ICDAP) 메뉴는 공통 포털 GNB에서 서비스 전환으로 진입 (동적 메뉴 구조 확정 후 반영)

## 4. 보류/확인 필요

- Data-Inside 가이드 수령 전이므로 색상 토큰·타이포는 잠정. 가이드 수령 시 Figma 톤과 조율
- 버전 비교의 행 단위/텍스트 단위 Diff 확장 여부 — 미팅 P1 답변에 따름
- 사양서 목록 카드형 vs 테이블형 기본값 — 실데이터 건수(P1) 확인 후 결정
- 샘플의 32필드 구성이 실제 "API 공통 규격서" 표준인지, 예시인지 확인 필요
