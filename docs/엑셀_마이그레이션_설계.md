# 엑셀 사양서 마이그레이션 — 전략과 화면 (FR-115)

> **왜 지금 적나.** 사양서는 **지금 엑셀로 관리되고 있고**, 최초 이관은 그 엑셀 파일을 받아
> 올리는 것으로 시작한다(2026-08-19 사용자). 요구사항에도 있다 —
> **FR-115 사양서 대량 업로드·파싱**(우선순위 S):
> "Excel/CSV **템플릿 기반** 대량 업로드, 파싱·검증·오류 리포트, **부분 반영** 처리".
> 수용기준 셋: ① 템플릿이 제공되고 **형식 위반이 사전 차단**된다 ② **오류 행이 사유와 함께
> 리포트**로 제공된다 ③ **정상 행만 부분 반영**하는 정책이 동작한다.
>
> ⚠ 화면이 먼저 나가면 그게 규칙이 된다(작업 규율). 그래서 **규칙을 먼저 적고** 화면을 만든다.

---

## 1. 무엇을 옮기나 — 두 층을 가른다

엑셀 한 파일에 두 가지가 섞여 온다. 섞인 채로 받으면 "행 하나가 무엇인지"가 흔들린다.

```
① 사양서 대장   한 행 = 사양서 한 건      (이름·카테고리·설명·태그·담당·버전)
② 필드 정의     한 행 = 사양서의 필드 하나 (사양서ID·항목·타입·필수·최대길이·유효성·담당·상태)
```

- **한 번에 하나만 올린다.** 업로드 화면이 먼저 "무엇을 올리는지"를 고르게 한다.
- ②는 ①이 있어야 붙는다 — 사양서ID가 대장에 없으면 그 행은 **오류**다(뒤 §4).

## 1-1. ⚠ 받는 파일은 **우리 템플릿이 아니다** (2026-08-19 사용자)

실제 사양서 엑셀은 이런 모양이다 — 템플릿을 강요하면 **사람이 손으로 옮겨 적어야 한다.**

```
통합문서 하나
 ├─ 시트 "VN7 엔진 사양서"   ← 시트 이름 = **사양서 명**
 │    1행: 항목코드 항목명 타입 필수 …   ← 최상단 행 = **컬럼명(= 필드명)**
 │    2행~: ENG001  엔진형식  string  Y …  ← 각 행 = **실 데이터**
 └─ 시트 "전기차 배터리 규격서"
```

그래서 **두 가지 길**을 연다. 화면이 먼저 "어느 길인지" 고르게 한다.

| 길 | 언제 | 사양서 명 | 필드 | 데이터 |
| --- | --- | --- | --- | --- |
| **원본 엑셀** (기본) | 지금 쓰는 파일을 그대로 | **시트 이름** | 머리 행의 **각 열** | 나머지 행 |
| 템플릿 | 새로 만들어 올릴 때 | `사양서명` 열 | 별도 시트/파일 | — |

⚠ **원본 길에서는 매핑이 필수다.** 파일마다 머리 행 위치가 다르고(제목·설명이 위에 몇 줄),
시트에 "목차"·"변경이력" 같은 **사양서가 아닌 시트**가 섞인다. 그래서 화면이 묻는다:

1. **어느 시트를 가져올까** — 시트마다 체크(기본: 전부). 목차·이력 시트는 빼면 된다
2. **머리 행이 몇 번째 줄인가** — 미리보기에서 고른다(위쪽 설명 줄은 자동으로 건너뛴다)
3. **각 열을 무엇으로 볼까** — 필드명은 열 이름 그대로, **타입은 값에서 추론**하고
   사람이 고친다. 안 가져올 열은 **제외**로 표시한다

⚠ **추론은 제안이지 판단이 아니다.** 타입을 자동으로 정하고 넘어가면 잘못 잡힌 타입이
그대로 사양서가 된다 — 화면이 추론 결과를 **보여 주고 고치게** 한 뒤 넘어간다.

## 2. 표준 양식은 **우리가 초안을 먼저 그린다** (템플릿 길)

> 2026-08-19 사용자: "실물 엑셀 양식은 나중에, 지금은 초안만 우리가 먼저 작성하는 형태로."
> ⚠ 양식이 없으면 회의가 말로만 돈다. 초안이 있으면 "이 열은 우리 쪽에 없다 / 이건 두 칸으로
> 나뉜다" 같은 **구체적인 반론**이 나온다 — 그게 실물을 당기는 가장 빠른 길이다.
>
> 초안은 업로드 화면의 **[표준 양식 받기 (xlsx)]** 로 내려받는다(`HMG_사양서_이관_표준양식_초안.xlsx`).
> 시트 셋: **읽어보기**(규칙을 글로) · **사양서 대장** · **필드 정의**.
> ⚠ 열 정의의 정본은 코드의 `TEMPLATE` 하나다 — 양식 파일은 그것을 옮겨 적을 뿐이라
> 열을 고치면 검증과 내려받는 양식이 **함께** 바뀐다(두 벌이 되면 반드시 어긋난다).
> ⚠ CSV 로 주지 않는다: 받는 쪽은 엑셀로 일하고, 우리 양식은 시트가 둘 필요하다(§1).

받는 엑셀이 회사마다 다르므로 **우리 템플릿으로 한 번 접는다.** 템플릿을 안 쓰면 열 이름이
매번 달라 매핑을 사람이 매번 새로 해야 하고, 그 매핑은 어디에도 안 남는다.

### 2-1. 사양서 대장 템플릿 (필수열 ★)

| 열 이름 | 필수 | 값 | 검증 |
| --- | --- | --- | --- |
| 사양서명 ★ | ● | 텍스트 | 공백 불가 · 200자 이내 · 대장 안 중복 금지 |
| 카테고리 ★ | ● | `파워트레인` \| `전동화` \| `자율주행` \| `차체/안전` | **정본 밖 값은 오류**(`data/specs.ts` `SPEC_CATEGORIES`) |
| 설명 | | 텍스트 | 1000자 이내 |
| 태그 | | `쉼표,구분` | 태그당 20자 이내 |
| 담당자 | | 회원 이름 | 회원 명단에 없으면 **경고**(비워서 올림) |
| 버전 | | `v0.1` 형식 | 없으면 `v0.1` |

### 2-2. 필드 정의 템플릿

| 열 이름 | 필수 | 값 | 검증 |
| --- | --- | --- | --- |
| 사양서명 ★ | ● | 대장의 사양서명 | 못 찾으면 오류 |
| 카테고리(대/중/소) | | 텍스트 | — |
| 필드명 ★ | ● | 텍스트 | 같은 사양서 안 중복 금지 |
| 타입 ★ | ● | `string` \| `number` \| `select` \| `text` \| `boolean` \| `date` | 정본 밖 값 오류 |
| 필수 | | `Y` \| `N` | 그 외 오류 |
| 최대길이 | | 정수 | 타입이 `number`/`date` 면 무시(경고) |
| 유효성 | | 정규식 | 컴파일 실패 시 오류 |
| 상태 | | `완료` \| `진행중` \| `검토중` \| `미완료` | 없으면 `미완료` |

> ⚠ **값은 한국어 정본 그대로 받는다.** 카테고리·상태를 영문으로 받지 않는다 — 화면은 표시만
> 영문으로 옮기고(사전 `specCategory.*`·`fieldStatus.*`) 값은 이 문자열로 맞물린다.
> 영문 헤더를 허용하면 매핑이 두 벌이 된다.

## 3. 형식 위반은 **사전 차단** (AC ①)

파일을 고르는 순간 아래를 먼저 본다. 여기서 막히면 **한 행도 읽지 않는다.**

1. 확장자 — `.xlsx` · `.xls` · `.csv` 만
2. 크기 — 10MB 초과는 거부(그 이상은 분할 요청). ⚠ 실제 상한은 서버 확정 후 조정
3. 헤더 — 필수열(★)이 전부 있는지. 하나라도 없으면 **어느 열이 없는지 이름으로** 말한다
4. 행 수 — 0행이면 "빈 파일"로 돌려보낸다

> ⚠ **xlsx 는 시트가 있어야 읽을 수 있다.** 원본 길은 "시트 = 사양서"라 CSV 로는 애초에
> 표현이 안 된다(CSV 에 시트가 없다). 그래서 xlsx 를 **직접 읽는다** — 통합문서는 zip 이고
> 그 안의 XML 몇 개면 시트 이름·셀 값이 나온다(`lib/xlsx.ts`, 라이브러리 없이 브라우저
> `DecompressionStream` 으로 푼다). 수식·서식·병합은 안 본다 — **값만** 읽는다.
> 본개발에서 서버 파싱(POI/openpyxl)으로 옮기면 화면은 그대로 두고 읽는 자리만 바뀐다.

## 3-1. ⚠ **열이 수백, 행이 수만**일 수 있다 (2026-08-19 사용자)

사양서 엑셀은 열이 200개, 행이 수만 개로 온다. 격자를 통째로 안고 그리면 탭이 멈춘다.
그런데 **이관에 정작 필요한 것은 머리 행과 앞쪽 몇 행뿐**이다(필드 이름·타입 제안·예시 값).

```
읽기   앞 200행만 담고(KEEP_ROWS), **행 수는 파일 전체를 센다**
       └ "자료 12,480행"은 전체 셈, 타입 제안은 표본 — 두 숫자를 섞으면 화면이 거짓말을 한다
       └ 표본으로 추론했다는 사실을 검증 단계에서 **경고로 말한다**
화면   시트는 한 번에 하나만 펼친다 · 열은 앞 60개만 그리고 **찾기**로 만난다
       └ [전체 켜기/끄기]는 **지금 보이는 열**에만 걸린다(찾기로 좁힌 뒤 쓰면 "이 묶음만"이 된다)
       └ 읽는 동안 "읽는 중…"을 띄운다 — 몇 초 멈춰 있으면 사람이 다시 누른다
막기   시트 XML 이 120MB(MAX_SHEET_BYTES, ≈셀 200만) 를 넘으면 **읽기 전에** 돌려보낸다
       └ 크기는 zip 목록에 적혀 있다 — 다 읽고 나서 "너무 큽니다"라고 하면 이미 늦다
```

⚠ **열이 많다고 막지 않는다.** 100개를 넘으면 경고로 "필요 없는 열은 꺼 주세요"라고 말할 뿐,
가져가는 것은 그대로다 — 실제로 다 필요한 사양서가 있다.
⚠ 지금은 **첫 자료 행만** 예시 값으로 남기므로, 행이 몇 만이어도 저장되는 양은 늘지 않는다.
자료 자체의 적재는 §7 미정 — 정해지면 그때는 서버 파싱이어야 한다(브라우저로는 못 든다).

## 4. 검증과 오류 리포트 (AC ②)

행마다 **위치(행 번호) · 열 · 사유**를 남긴다. "형식이 잘못됐습니다"는 리포트가 아니다.

```
행 12 · 카테고리 · 정본에 없는 값입니다: '파워트레인/전동화' (허용: 파워트레인, 전동화, 자율주행, 차체/안전)
행 27 · 사양서명 · 파일 안에서 중복됩니다 (행 9 와 같음)
행 31 · 유효성  · 정규식을 해석할 수 없습니다: '^[A-Z{2}$'
```

- **오류**: 그 행은 안 들어간다.
- **경고**: 들어가되 값이 비워지거나 기본값으로 대체된다(담당자 못 찾음, 최대길이 무시 등).
- 리포트는 화면 표 + **CSV 내려받기** 두 가지로 준다 — 엑셀로 고칠 사람은 파일이 필요하다.

## 4-1. 필드 정의는 **덮어쓴다** (대장은 건너뛴다)

같은 파일을 다시 올렸을 때의 규칙이 층마다 다르다 — 다른 이유가 있다.

| 층 | 이미 있으면 | 왜 |
| --- | --- | --- |
| 사양서 대장 | **건너뛴다**(경고) | 사양서는 *물건*이다. 다시 만들면 이력이 갈라진다 |
| 필드 정의 | **덮어쓴다** | 필드는 *정의*다. 엑셀에서 고쳐 다시 올리는 것이 이 제품의 기본 왕복이라, 덮어쓰지 않으면 고친 값이 안 들어가거나 표가 두 배가 된다 |

⚠ **결재 중인 사양서의 필드는 못 고친다** — 엑셀 한 장이 승인자가 본 문서를 몰래 바꾸면
이력이 못 믿을 것이 된다. 검증이 그 행을 오류로 막는다(API 설계 §1 의 409 와 같은 규칙).

## 4-2. 왕복 — 내려받아 고쳐 다시 올린다

```
사양서 상세 [Excel 다운로드]  →  엑셀에서 고친다  →  [엑셀 업로드]  →  표에 반영
        └ 내보내는 열 이름 = 읽는 열 이름 (`TEMPLATE.fields` 정본 하나)
```

⚠ 두 이름이 갈리면 내려받은 파일을 그대로 올릴 수 없다 — 사람이 열을 손으로 맞추게 된다.
⚠ 상세에서 올릴 때는 **사양서명 열이 없어도 된다**(그 화면이 곧 사양서다). 대신 다른
사양서 이름이 적혀 있으면 오류로 막는다 — 엉뚱한 사양서에 붙는 것이 가장 위험하다.

## 5. 부분 반영 정책 (AC ③)

```
정상 행만 반영한다. 오류 행은 남는다.
  ├ 반영 결과: "42건 중 39건 반영 · 3건 오류"
  ├ 오류 3건은 리포트로 받아 고친 뒤 **다시 올린다**(같은 파일 전체를 다시 올려도 된다)
  └ ⚠ 이미 반영된 39건은 **중복으로 다시 안 들어간다** — 사양서명이 같으면 '이미 있음'으로
     건너뛴다(경고). 되돌리기보다 **다시 올려도 안전한 것**이 실무에서 낫다.
```

- 전부 아니면 전무(all-or-nothing)로 하지 않는 이유: 40건 중 1건 때문에 39건을 다시
  기다리게 하면 사람이 파일을 쪼개기 시작한다 — 그러면 이력이 흩어진다.
- **되돌리기**: 프로토타입은 없다. 본개발에서는 업로드 배치 단위로 `batchId` 를 남기고
  "이 배치 되돌리기"를 관리자에게 준다(⚠ 미정 — PROJECT_CONTEXT 의 "롤백" 항목).

## 6. 화면 — 네 걸음 (사양서 관리 → [엑셀 업로드])

```
① 고르기      길 고르기(원본 엑셀 / 템플릿) · 템플릿 받기 · 파일 고르기
                └ 형식 위반은 여기서 막고 이유를 적는다 (§3)
② 매핑        [원본] 시트 고르기 · 머리 행 지정 · 열 → 필드(이름·타입·제외) — §1-1
                └ 큰 파일: 시트 접기 · 열 찾기 · 전체 켜기/끄기 · 앞 60개만 그리기 (§3-1)
              [템플릿] 열 매핑과 미리보기 5행 — "이 파일을 이렇게 읽었습니다"
③ 검증        정상 n · 경고 m · 오류 k · 오류 표 + 리포트 내려받기 (§4)
④ 반영        정상 행만 반영 → 결과 요약 + 다음 행동(목록 보기 / 오류 고쳐 다시 올리기)
```

- 되돌릴 수 없는 걸음은 **④ 하나뿐**이고, 그 앞에서 무엇이 들어갈지 숫자로 보여 준다(규약 §2).
- 걸음마다 **뒤로 갈 수 있다.** 파일을 다시 고르는 것이 가장 흔한 일이다.
- 큰 파일은 화면을 점유하지 않는다 — 프로토타입은 동기 파싱이지만, 1000행이 넘으면
  진행 표시를 띄운다(FR-081 의 "대용량은 비동기" 원칙과 같은 방향).
