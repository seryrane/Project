# 엑셀 사양서 마이그레이션 — 전략과 화면 (FR-115)

> **왜 지금 적나.** 사양서는 **지금 엑셀로 관리되고 있고**, 최초 이관은 그 엑셀 파일을 받아
> 올리는 것으로 시작한다(2026-08-19 사용자). 요구사항에도 있다 —
> **FR-115 사양서 대량 업로드·파싱**(우선순위 S):
> "Excel/CSV **템플릿 기반** 대량 업로드, 파싱·검증·오류 리포트, **부분 반영** 처리".
> 수용기준 셋: ① 템플릿이 제공되고 **형식 위반이 사전 차단**된다 ② **오류 행이 사유와 함께
> 리포트**로 제공된다 ③ **정상 행만 부분 반영**하는 정책이 동작한다.
>
> ⚠ 화면이 먼저 나가면 그게 규칙이 된다(작업 규율). 그래서 **규칙을 먼저 적고** 화면을 만든다.

---

## 1. 무엇을 옮기나 — 두 층을 가른다

엑셀 한 파일에 두 가지가 섞여 온다. 섞인 채로 받으면 "행 하나가 무엇인지"가 흔들린다.

```
① 사양서 대장   한 행 = 사양서 한 건      (이름·카테고리·설명·태그·담당·버전)
② 필드 정의     한 행 = 사양서의 필드 하나 (사양서ID·항목·타입·필수·최대길이·유효성·담당·상태)
```

- **한 번에 하나만 올린다.** 업로드 화면이 먼저 "무엇을 올리는지"를 고르게 한다.
- ②는 ①이 있어야 붙는다 — 사양서ID가 대장에 없으면 그 행은 **오류**다(뒤 §4).

## 2. 템플릿이 정본이다

받는 엑셀이 회사마다 다르므로 **우리 템플릿으로 한 번 접는다.** 템플릿을 안 쓰면 열 이름이
매번 달라 매핑을 사람이 매번 새로 해야 하고, 그 매핑은 어디에도 안 남는다.

### 2-1. 사양서 대장 템플릿 (필수열 ★)

| 열 이름 | 필수 | 값 | 검증 |
| --- | --- | --- | --- |
| 사양서명 ★ | ● | 텍스트 | 공백 불가 · 200자 이내 · 대장 안 중복 금지 |
| 카테고리 ★ | ● | `파워트레인` \| `전동화` \| `자율주행` \| `차체/안전` | **정본 밖 값은 오류**(`data/specs.ts` `SPEC_CATEGORIES`) |
| 설명 | | 텍스트 | 1000자 이내 |
| 태그 | | `쉼표,구분` | 태그당 20자 이내 |
| 담당자 | | 회원 이름 | 회원 명단에 없으면 **경고**(비워서 올림) |
| 버전 | | `v0.1` 형식 | 없으면 `v0.1` |

### 2-2. 필드 정의 템플릿

| 열 이름 | 필수 | 값 | 검증 |
| --- | --- | --- | --- |
| 사양서명 ★ | ● | 대장의 사양서명 | 못 찾으면 오류 |
| 카테고리(대/중/소) | | 텍스트 | — |
| 필드명 ★ | ● | 텍스트 | 같은 사양서 안 중복 금지 |
| 타입 ★ | ● | `string` \| `number` \| `select` \| `text` \| `boolean` \| `date` | 정본 밖 값 오류 |
| 필수 | | `Y` \| `N` | 그 외 오류 |
| 최대길이 | | 정수 | 타입이 `number`/`date` 면 무시(경고) |
| 유효성 | | 정규식 | 컴파일 실패 시 오류 |
| 상태 | | `완료` \| `진행중` \| `검토중` \| `미완료` | 없으면 `미완료` |

> ⚠ **값은 한국어 정본 그대로 받는다.** 카테고리·상태를 영문으로 받지 않는다 — 화면은 표시만
> 영문으로 옮기고(사전 `specCategory.*`·`fieldStatus.*`) 값은 이 문자열로 맞물린다.
> 영문 헤더를 허용하면 매핑이 두 벌이 된다.

## 3. 형식 위반은 **사전 차단** (AC ①)

파일을 고르는 순간 아래를 먼저 본다. 여기서 막히면 **한 행도 읽지 않는다.**

1. 확장자 — `.xlsx` · `.xls` · `.csv` 만
2. 크기 — 10MB 초과는 거부(그 이상은 분할 요청). ⚠ 실제 상한은 서버 확정 후 조정
3. 헤더 — 필수열(★)이 전부 있는지. 하나라도 없으면 **어느 열이 없는지 이름으로** 말한다
4. 행 수 — 0행이면 "빈 파일"로 돌려보낸다

> ⚠ **xlsx 파싱은 브라우저에서 공짜가 아니다.** 프로토타입은 **CSV 를 직접 파싱**하고,
> xlsx 는 "CSV 로 저장해 올려 주세요" 안내 + 템플릿 제공으로 받는다. 본개발에서 서버
> 파싱(POI/openpyxl)으로 옮기면 화면은 그대로 두고 업로드 대상만 바뀐다.

## 4. 검증과 오류 리포트 (AC ②)

행마다 **위치(행 번호) · 열 · 사유**를 남긴다. "형식이 잘못됐습니다"는 리포트가 아니다.

```
행 12 · 카테고리 · 정본에 없는 값입니다: '파워트레인/전동화' (허용: 파워트레인, 전동화, 자율주행, 차체/안전)
행 27 · 사양서명 · 파일 안에서 중복됩니다 (행 9 와 같음)
행 31 · 유효성  · 정규식을 해석할 수 없습니다: '^[A-Z{2}$'
```

- **오류**: 그 행은 안 들어간다.
- **경고**: 들어가되 값이 비워지거나 기본값으로 대체된다(담당자 못 찾음, 최대길이 무시 등).
- 리포트는 화면 표 + **CSV 내려받기** 두 가지로 준다 — 엑셀로 고칠 사람은 파일이 필요하다.

## 5. 부분 반영 정책 (AC ③)

```
정상 행만 반영한다. 오류 행은 남는다.
  ├ 반영 결과: "42건 중 39건 반영 · 3건 오류"
  ├ 오류 3건은 리포트로 받아 고친 뒤 **다시 올린다**(같은 파일 전체를 다시 올려도 된다)
  └ ⚠ 이미 반영된 39건은 **중복으로 다시 안 들어간다** — 사양서명이 같으면 '이미 있음'으로
     건너뛴다(경고). 되돌리기보다 **다시 올려도 안전한 것**이 실무에서 낫다.
```

- 전부 아니면 전무(all-or-nothing)로 하지 않는 이유: 40건 중 1건 때문에 39건을 다시
  기다리게 하면 사람이 파일을 쪼개기 시작한다 — 그러면 이력이 흩어진다.
- **되돌리기**: 프로토타입은 없다. 본개발에서는 업로드 배치 단위로 `batchId` 를 남기고
  "이 배치 되돌리기"를 관리자에게 준다(⚠ 미정 — PROJECT_CONTEXT 의 "롤백" 항목).

## 6. 화면 — 네 걸음 (사양서 관리 → [엑셀 업로드])

```
① 고르기      무엇을 올리나(대장/필드) · 템플릿 받기 · 파일 고르기
                └ 형식 위반은 여기서 막고 이유를 적는다 (§3)
② 확인        열 매핑과 미리보기 5행 — "이 파일을 이렇게 읽었습니다"
③ 검증        정상 n · 경고 m · 오류 k · 오류 표 + 리포트 내려받기 (§4)
④ 반영        정상 행만 반영 → 결과 요약 + 다음 행동(목록 보기 / 오류 고쳐 다시 올리기)
```

- 되돌릴 수 없는 걸음은 **④ 하나뿐**이고, 그 앞에서 무엇이 들어갈지 숫자로 보여 준다(규약 §2).
- 걸음마다 **뒤로 갈 수 있다.** 파일을 다시 고르는 것이 가장 흔한 일이다.
- 큰 파일은 화면을 점유하지 않는다 — 프로토타입은 동기 파싱이지만, 1000행이 넘으면
  진행 표시를 띄운다(FR-081 의 "대용량은 비동기" 원칙과 같은 방향).
