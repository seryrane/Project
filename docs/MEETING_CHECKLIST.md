# 1차 미팅 질문지 (2시간 기준)

> P1 = 미확정 시 아키텍처/공수 산정 불가. 미팅에서 반드시 결론 또는 확정 일정 수령.
> 각 항목 뒤 ( ) 안은 답변 기록란.

## Session 1 — 프로젝트 범위·전략 (30분)

**플랫폼 전략 [P1]**
- [ ] KPI(ICDAP)/IBD(IDMS) 단일 포털·단일 도메인으로 운영하는가? 도메인 확보/인증서 절차는? ( )
- [ ] 서비스 분리는 메뉴 방식인가 URL 방식인가? 타 시스템 탑재는 URL 연동 수준인가 컴포넌트 결합 수준인가? ( )
- [ ] 향후 추가 시스템은 몇 개, 언제인가? (IBD 2.0 등) ( )
- [ ] 플랫폼 소유/운영 주관 부서는? 오픈 후 운영조직(권한/결재선/Rule/대시보드/메뉴 관리 주체)은? ( )

**목표·범위 [P1]**
- [ ] 프로젝트 성공 KPI는? (예: 사양 등록 시간 50%↓, 검증 자동화율 80%, 결재기간 5일→1일) ( )
- [ ] MVP(1차 오픈 필수 기능) 범위와 이번 사업 제외 범위는? ( )
- [ ] 예상 사용자 수 / 최대 동시 접속자 수는? ( )

**기술 표준 [P1 — Critical]**
- [ ] 백엔드 프레임워크 확정: FastAPI인가 Spring Boot인가? (요구사항서 "B/E: 협의") ( )
- [ ] 기존 KPI 플랫폼 소스(Git) 제공 여부와 재사용 범위(SSO/RBAC/메뉴/게시판/알림/감사로그)는? ( )
- [ ] DEV/(SIT)/UAT/PRD 제공 시점, hCloud VM 스펙, PostgreSQL 버전, GitLab CI/CD 권한은? ( )
- [ ] 개발인력 보안 PASS제: 필수 조건 범위(경험/시큐어코딩 이수증/자격증)와 증빙 제출 시점은? ( )

## Session 2 — 사양서 관리(IDMS) (40분)

**데이터 구조 [P1]**
- [ ] 사양서 종류 수 / Excel 템플릿 유형 수는? 국가별 양식 차이가 있는가? ( )
- [ ] 관리 단위(레코드 기준)와 Event/Signal/Parameter/Attribute 구조는? 데이터 Dictionary가 있는가? ( )
- [ ] 국가/플랫폼/차종(+연식) 축과 계층(대분류/중분류/항목) 구조는? ( )
- [ ] 고유 식별자(Key) 정책은? ( )
- [ ] 전체 데이터 건수 규모는? ( )

**버전 관리 [P1]**
- [ ] 버전 생성 기준과 형식(v1.0 vs 날짜형)은? Major/Minor 기준은? ( )
- [ ] 작업버전/배포버전 구분이 필요한가? T-N주(배포 기준) 운영 방안의 현재 상태는? ( )
- [ ] 비교(Diff)는 행/컬럼/텍스트 중 어느 단위까지? ( )
- [ ] 폐기 버전 보관 정책은? ( )

**엑셀 마이그레이션 [P1]**
- [ ] 파일 수 / 양식 수 / 총 Row 수 / 평균·최대 파일 크기는? ( )
- [ ] 이관 범위(전체/일부), 오류 데이터 정제 필요 여부, 정합성 검증 기준은? ( )
- [ ] 업로드 취소(롤백) 기능이 필요한가? ( )
- [ ] ★ 샘플 파일 확보: 정상 / 오류 / 대용량 각 1개 이상 ( )

**검색·조회**
- [ ] 검색 조건(국가/차종/버전 등)과 최대 조회 건수는? ( )
- [ ] Excel/PDF 출력 요건은? 대용량 다운로드의 구체적 최대 건수와 허용 포맷(CSV만? Excel 필수?)은? ( )

## Session 3 — 검증엔진·데이터 연계 (30분)

**검증 Rule [P1 — 공수 최대 변수]**
- [ ] 기존 검증 Rule이 존재하는가? 문서화되어 있는가? ( )
- [ ] Rule 개수 규모: 10개 이하 / 100개 / 1000개 이상? ( )
- [ ] Rule 작성 주체: 개발자인가 현업(운영자)인가? → 아키텍처 분기(FastAPI+라이브러리 vs Rule Engine+DSL+Admin Builder, 공수 3배 차이) ( )
- [ ] Rule 변경 빈도: 월 1회 / 주 1회 / 수시? ( )
- [ ] 현 Airflow 기반 운영의 이관 범위는? CSV 업로드 + 버전관리 + 반영 전 테스트 절차 요구가 맞는가? ( )
- [ ] Python 검증 함수 수, I/O 규격, 제공 방식(HMC 제공?), 롤백/버전관리 요건은? ( )

**검증 수행·성능**
- [ ] 실시간/배치 여부, 검증 주기, 수동 실행·재실행·오류 재처리 요건은? ( )
- [ ] 일일/월간 검증 데이터량(10만/100만/1000만 건)과 최대 처리 시간(SLA)은? ( )
- [ ] 검증 결과: 저장 항목, 오류 분류 체계, 품질 KPI, 리포트(Excel/PDF)·대시보드 요건은? ( )

**데이터 연계 [P1]**
- [ ] CDO 연계는 Kafka인가 SFTP인가? 확정 시점은? ( )
- [ ] (Kafka인 경우) Topic 수, Message Format(JSON/Avro/Protobuf), Schema Registry, Consumer 정책, 인증 방식은? ( )
- [ ] ★ Kafka 샘플 메시지 확보 ( )
- [ ] 데이터마트: 구축 주체(발주처/운영조직/본 사업)와 완료 시점은? 지연 시 Mock Data/Swagger 제공 수준은? ( )

**결재 [P1]**
- [ ] 신규/수정/삭제 요청별 결재 프로세스와 최대 단계 수는? (예: 담당자→팀장→실장→승인) ( )
- [ ] 결재선 동적 변경, 자동 생성, 대결, 참조, 반려·재상신, 승인 후 수정 정책은? ( )
- [ ] 동일 사양 다중 수정 요청 충돌 — **화면은 이미 만들어 두었다**(2026-08-21): 신청은 안 막고,
      겹치면 목록에 붙여 세우고, **반영만** 막고, 하나를 고른 뒤 나머지를 사유와 함께 취소한다.
      회의(2026-07-20)에서 정한 그대로다. **물을 것은 남은 세 가지뿐이다** — 실물을 보여 주고 묻는다:
  - [ ] 마지막 요청이 앞의 것을 **자동으로 덮어쓰는** 정책도 필요한가? (지금은 사람이 고른다) ( )
  - [ ] 대기 풀에 이미 한 건이 있으면 **입력 시점부터** 알릴까? (회의에서 제안됐고 결론 없음) ( )
  - [ ] 취소된 건은 **별도 탭**으로 뺄까, 지금처럼 [처리됨]에 섞을까? ( )
