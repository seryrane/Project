# 퍼블리싱 가이드 — 새 화면을 규칙대로 짜는 법

> 이 문서는 **퍼블리셔(마크업·스타일 담당)** 를 위한 것이다.
> 여기는 **"실무 사용법"의 정본** — 어떤 클래스 조합을, 어떤 관문 컴포넌트로, 왜 그렇게 쓰는가.
> **시각 토큰 값**(색 hex·스케일·모션 곡선)의 정본은 `frontend/DESIGN.md`, **화면이 언제 무엇을
> 보여 주는가**의 정본은 `docs/화면_공통규칙.md` 다 — 이 문서는 그 둘을 가리키기만 하고
> 값을 다시 베끼지 않는다. 값이 바뀌면 이 문서가 아니라 저 둘이 바뀐다.

---

## 1. 색·치수는 토큰에서만 고른다

hex를 직접 적지 않는다. `@theme`(`frontend/src/styles.css`)에 없는 값이 필요해 보이면
**단계가 틀린 것**이다 — 화면이 아니라 토큰부터 늘려야 한다(값은 `frontend/DESIGN.md`가 정본).

| 토큰 | 뜻 | 쓰는 자리 |
|---|---|---|
| `canvas` | 페이지 배경 | `bg-canvas` — `<body>`·패널 머리(`bg-canvas/50`). **헤더에는 안 쓴다**(아래 `topbar`) |
| `topbar` (+`topbar-line`, `shadow-topbar`) | 앱 헤더(GNB)가 앉는 **크롬 면** | `bg-topbar border-topbar-line shadow-topbar` — `AppShell` 헤더 한 곳. 캔버스와 같은 색이면 라이트에서 헤더·본문이 붙는다(2026-08-11) |
| `surface` | 카드·모달·입력의 배경 | `bg-surface` — 카드, `<Modal>`/`<Drawer>` 본체, 입력 |
| `field` | **조작이 앉는 면**(검색칸·아이콘 버튼·칩) | `bg-field` — 라이트에서만 흰 면보다 한 단계 눌린다. **흰 헤더 위의 GNB 조작은 `bg-surface` 가 아니라 이것** |
| `raised` | 카드 안의 인셋 박스 | `bg-raised` — 토스트, 버전 비교 셀 |
| `hairline` | 1px 경계선 | `border-hairline` — 거의 모든 테두리. 콘텐츠 영역의 **기본 보더는 이것 하나** |
| `ink` | 본문·제목 글자 | `text-ink` |
| `ink-muted` | 보조 글자 | `text-ink-muted` |
| `ink-subtle` | 레이블·캡션 | `text-ink-subtle` |
| `primary` / `primary-deep` | 액센트(버튼·활성·포커스) | `bg-primary`, `text-primary`, `border-primary/40`, hover는 `primary-deep` |
| `accent2` | 그라디언트 짝 색 | `from-primary to-accent2` — CTA·활성 메뉴·로고 |
| `chip` / `chip-strong` | 콘텐츠 영역의 **중립 반투명 면** | `bg-chip`(hover 배경), `bg-chip-strong`(선택 상태 면) — `white/5`·`white/10`이 할 일을 콘텐츠 영역에서 대신한다 |
| `glow` | 액센트 발광 | `shadow-[0_2px_10px_var(--color-glow)]`, `.card-spotlight`/`.card-hover`가 내부에서 씀 |
| `sidebar` / `sidebar-ink` | 사이드바 전용 배경·글자 | `bg-sidebar`, `text-sidebar-ink` — 사이드바 밖에서는 안 쓴다 |
| `draft` / `review` / `pending` / `deployed` / `danger` (각 `-bg`/`-ink`) | 상태 배지 | `bg-review-bg text-review-ink` 식 쌍으로만. 배지 전용 — 카드 전체 배경엔 안 씀 |
| `added` (`-bg`/`-ink`) | 버전 diff의 "추가/변경 후" | `VersionCompareModal`의 diff 셀 전용. 삭제 쪽은 `danger` 재사용 |
| `fill-draft/review/pending/deployed` | **차트 마크 전용** 상태색 | `charts.tsx`의 `fill`/`color` prop — CVD 검증 통과본. 배지용 `-ink` 색을 차트 필로 재사용하지 않는다(검증 실패 조합) |

**`white/*` 유틸은 콘텐츠 영역에서 금지, 사이드바 안에서만 허용.** 이유: 라이트 테마는
`canvas`·`surface`가 흰색 계열로 뒤집히는데 `white/8` 보더는 흰 배경 위에서 거의 안 보인다
— 실제로 `AppShell.tsx`의 사이드바(`<aside>`)는 `border-white/5`·`hover:bg-white/5`를 쓰고,
같은 파일의 헤더·GNB 팝오버(콘텐츠 영역)는 전부 `border-hairline`·`hover:bg-chip`으로
갈아 놓았다 — **사이드바는 두 테마 모두 다크라 white/*가 안전하고, 콘텐츠는 테마를 타야
하니 토큰만 쓴다.** 모달 오버레이의 `bg-black/65`처럼 흑백 자체가 목적인 경우(배경 스크림)는
예외다 — 그건 색이 아니라 어둡게 가리는 효과다.

라운드·간격도 마찬가지: 카드·모달은 `rounded-2xl`(16px), 버튼·입력은 `rounded-lg`(8px),
배지·칩은 `rounded-full`. 페이지 콘텐츠 폭은 `max-w-7xl`(1280px) + `px-4 pc:px-8`.
숫자에는 반드시 `tabular-nums`(금액·건수·표 안 숫자 전부).

## 2. 테마 두 벌

`<html data-theme="light">`가 토큰을 통째로 갈아끼운다 — `AppShell.tsx`의 `useTheme` 훅이
`document.documentElement.dataset.theme`을 쓰고 `localStorage('theme')`에 저장한다. 컴포넌트는
아무것도 몰라도 된다: 토큰(`bg-surface`, `text-ink` 등)만 쓰면 자동으로 따라온다.

**사이드바는 두 테마 모두 다크(브랜드)다.** `styles.css`의 `[data-theme='light']` 블록에
`--color-sidebar`/`--color-sidebar-ink` 오버라이드가 **없다** — 그래서 라이트에서도 사이드바만
어둡게 남는다. 사이드바 안에서 만드는 요소는 `sidebar`/`sidebar-ink` 또는 `white/*`를 쓰고,
콘텐츠 영역 토큰(`ink`, `surface`)을 끌어오지 않는다(라이트에서 사이드바가 밝아져 버린다).

**라이트에서 확인할 것 (새 화면마다):**
- 보더가 보이는가 — `hairline`이 라이트에서는 `#e3e7f0`로 옅다. `white/*`가 하나라도 남으면 이때 사라진다.
- 상태 배지 5종 대비 — 라이트 배지는 `-bg`가 밝고 `-ink`가 진해지는 반전이라, 하드코딩한 색이 있으면 여기서만 안 바뀐다.
- `.card-spotlight`/`.card-hover`의 글로우가 라이트에서도 옅게 보이는가(진해 보이면 `glow` 알파를 손대는 게 아니라 토큰이 잘못 덮인 것).
- 스크롤바(`chip-strong` 기반)가 흰 배경에서도 식별되는가.
- 다크에서만 테스트하고 끝내지 않는다 — 상단바 해/달 토글로 즉시 전환해 눈으로 본다.

## 3. 포인트 색상(개인 설정) — hex를 적으면 그 자리만 옛 색으로 남는다

`<html data-accent="...">`가 강조 4토큰(`primary`·`primary-deep`·`accent2`·`glow`)만
갈아끼운다. 기본값은 **현대 남색(navy)** 이라 속성 자체가 없다(`lib/accent.ts`의
`DEFAULT_ACCENT = 'navy'`). 선택지는 `navy`(기본)·`violet`·`blue`·`green`·`amber`·`rose`
6종, 정본은 `lib/accent.ts`(`styles.css`의 accent 블록과 1:1).

**지킬 것 — 새 화면을 만들 때:**
- 강조가 필요한 자리는 반드시 `primary`/`primary-deep`/`accent2`/`glow` **토큰**으로 쓴다.
  `bg-gradient-to-r from-primary to-accent2`, `text-primary`, `border-primary/40`,
  `shadow-[0_2px_10px_var(--color-glow)]` — 이 조합이면 사용자가 포인트 색을 바꾸는 순간
  화면 전체가 같이 바뀐다.
- **hex·rgb를 직접 적은 강조색은 그 자리 혼자 옛 색(남색)으로 남는다** — 6절 규칙(토큰만)이
  여기서 실제로 값을 한다. `charts.tsx`의 시리즈 색처럼 **상태를 나타내는 색**(`fill-draft` 등)은
  예외 — 그건 포인트 색이 아니라 뜻이 정해진 색이라 accent를 안 따라간다(22절).
- `bg-gradient-to-r from-primary to-accent2` 조합 클래스 문자열은 `styles.css`의 CTA 셴
  효과(`[class*='from-primary'][class*='to-accent2']`)를 그대로 트리거한다 — **주 CTA에만**
  쓴다. 장식으로 아무 데나 이 조합을 쓰면 의도치 않게 빛이 스치는 버튼이 생긴다.
- 상태 배지·diff 색(`draft`/`review`/`pending`/`deployed`/`danger`/`added`)은 accent와
  무관하게 고정이다 — 절대 `primary`로 바꿔 쓰지 않는다("승인 대기"가 사용자가 고른
  포인트 색으로 보이면 상태가 아니라 강조로 읽힌다).

## 4. 레이아웃 뼈대

### 셸

라우트 컴포넌트는 전부 `<AppShell active="라우트키" title="...">...</AppShell>`로 감싼다.
`AppShell`이 사이드바(데스크톱 고정폭 240px/레일 64px·모바일 서랍) + 글래스 헤더 +
`max-w-7xl` 본문 컨테이너 + 앰비언트 글로우 1개를 전부 그린다. 퍼블리셔가 셸을 직접
짜지 않는다 — `active`가 사이드바 활성 아이템과 헤더의 현재 위치 라벨을 동시에 맞춘다
(규약 §15: 이름이 두 곳에서 어긋나면 있는 화면도 없는 것처럼 보인다).

### 페이지 머리 블록 (모든 목록형 화면이 같은 모양)

```tsx
<div className="flex flex-wrap items-start justify-between gap-3">
  <div>
    <h1 className="text-2xl font-bold">{title}</h1>
    <p className="mt-1 text-[13px] text-ink-subtle">{subtitle}</p>
  </div>
  <button
    type="button"
    className="h-9 rounded-lg bg-gradient-to-r from-primary to-accent2 px-4 text-[13px] font-semibold text-white shadow-[0_2px_10px_var(--color-glow)] transition-opacity hover:opacity-90"
  >
    + 등록
  </button>
</div>
```

`flex-wrap`이 없으면 좁은 화면에서 제목과 버튼이 한 줄로 눌린다 — 넘치면 줄을 바꾸지
페이지를 밀지 않는다(규약 §4-5).

### 카드

```
rounded-2xl border border-hairline bg-surface p-5
```
그 위에 상황별로 얹는다: `card-spotlight`(포인터 추적 은은한 빛 — 정적인 정보 카드),
`card-hover`(클릭 가능한 카드의 호버 뜸+글로우 — 반드시 `cursor-pointer`와 짝),
`anim-fade-up`(목록 진입 시 등장, `style={{ animationDelay: \`${i * 70}ms\` }}`로 순서를
줌 — 60~80ms 간격). **`card-hover`와 `layout`(motion) 요소를 같이 쓰지 않는다** — 10절 참조.

### 통계 타일 행

```
grid grid-cols-2 gap-4 xl:grid-cols-4
```
각 타일은 `card-spotlight rounded-2xl border border-hairline bg-surface px-5 py-4`,
값은 `text-2xl font-semibold tabular-nums`. 대시보드용 차트 포함 타일은
`components/portal/charts.tsx`의 `StatTile`/`ChartCard`를 쓴다 — 직접 SVG를 새로 그리지
않는다(마크 규칙은 10절, dataviz 스킬 정본).

### 표 (데스크톱)

```tsx
<div className="mt-4 hidden overflow-x-auto card-spotlight rounded-2xl border border-hairline bg-surface pc:block">
  <table className="w-full min-w-[860px] border-collapse text-[13px]">
    <thead>
      <tr className="border-b border-hairline bg-canvas/60 text-left text-xs text-ink-subtle">
        <th className="px-4 py-2.5 font-medium">이름</th>
        ...
      </tr>
    </thead>
    <tbody>
      <tr className="cursor-pointer border-b border-hairline/60 transition-colors last:border-0 hover:bg-chip">
        ...
      </tr>
    </tbody>
  </table>
</div>
```
숫자 열은 `text-right tabular-nums`, 빈 값은 `—`. 이 프로젝트는 아직 공통 `DataTable`
관문이 없다 — 화면마다 위 골격을 그대로 반복해서 쓰고 있으니(§9는 계획이지 완료가 아니다),
새 표도 이 골격을 따른다. `members.tsx`·`roles.tsx`가 실 사용례다.

### 폼 필드

```tsx
<label className="block">
  <span className="text-xs font-medium text-ink-subtle">
    이름 <b className="text-danger-ink">*</b>
  </span>
  <input
    className="mt-1 h-10 w-full rounded-lg border border-hairline bg-canvas/60 px-3 text-[13px] outline-none focus:border-primary/60"
  />
</label>
```
필수 표시는 `<b className="text-danger-ink">*</b>`. 셀렉트는 원시 `<select>`가 아니라
`components/portal/Select.tsx`(체브론을 입힌 관문), 옵션 ≤6개의 단일/다중 선택은
`ChipSelect`/`ChipMulti`(3절 참조), on/off 하나는 `Switch` — 원시 체크박스는 쓰지 않는다
(DESIGN.md Rules 10).

## 5. 표시 영역 4종의 마크업

정본은 `docs/화면_공통규칙.md` §1 — **언제 MAIN/RIGHT/BOTTOM/MODAL 인지**는 거기서 판단한다.
여기는 퍼블리셔가 실제로 여는 방법만.

| 영역 | 관문 컴포넌트 | 여는 법 |
|---|---|---|
| **MAIN** | 없음 — `AppShell` children이 곧 본문 | 라우트 컴포넌트 자체 |
| **RIGHT** | `components/portal/Drawer.tsx` | `<Drawer title={...} onClose={...}>{(close) => <>...</>}</Drawer>` |
| **BOTTOM** | **아직 없음** | 검증 로그 등 흐르는 콘솔용 관문이 이 저장소엔 아직 없다. 필요해지면 화면마다 새로 만들지 말고 `Modal`/`Drawer`와 같은 구조(머리·몸·발, Esc, 배경막 없음, `max-height 60vh`)로 먼저 관문을 세운다 |
| **MODAL** | `components/portal/Modal.tsx` | `<Modal title={...} onClose={...} wide?>{...}</Modal>` |

**직접 만들지 않는다** — `fixed inset-0` + 오버레이 + 애니메이션을 화면마다 새로 짜면
Esc·바디락·모바일 시트 전환이 화면마다 갈린다. 위 둘은 이미 다음을 전부 처리한다:

- Esc로 닫힘, `Modal`은 배경막 클릭도 닫힘(RIGHT는 배경막 자체가 없다 — 대조가 목적)
- 열려 있는 동안 `body`+`html` 스크롤 잠금(스크롤바 트랙 폭까지 계산됨 — 직접 만들면
  이 부분을 놓치기 쉽다)
- 모바일에서 `Modal`은 자동으로 아래에서 올라오는 시트(`items-end pc:items-center`,
  `rounded-t-2xl pc:rounded-2xl`)가 된다 — 별도 분기 코드 불필요
- 퇴장 애니메이션이 끝난 뒤 언마운트(`onAnimationComplete`) — `setTimeout` 어림 금지가
  이미 구현돼 있다

**`Drawer`는 `onClose`가 아니라 children 함수가 주는 `close`를 눌러야 한다** — 내부
버튼(취소·완료 후 닫기)은 `children={(close) => ...}`의 `close`를 부른다. `onClose`를
직접 부르면 퇴장 애니메이션 없이 즉시 사라진다.

## 6. 반응형

브레이크포인트는 `pc:`(720px) 하나, **좁은 화면이 먼저다** — Tailwind 기본(`md:` 등)처럼
"이 폭 이상일 때 적용"이 아니라 여기서도 문법은 min-width라 `pc:flex`는 "720px부터 flex"란
뜻은 같지만, **기본(접두사 없는) 클래스를 좁은 화면 값으로 적고 `pc:`로 넓은 화면을 켠다는
순서로 짠다** — 이 저장소 화면은 전부 모바일 우선으로 쓰여 있다(`flex-col pc:flex-row`,
`hidden pc:block` 등). 새 화면도 이 순서를 지킨다: 기본 클래스가 모바일 모양, `pc:`가 예외.

터치 타깃: 조작 최소 `min-height 40px`(표·칩 안은 36px 타협), 입력 글자 16px 이상(그
아래면 iOS가 확대), `input`도 `min-height 40px`. **`height`가 아니라 `min-height`** — 두 줄
항목이 잘리지 않게. `styles.css`의 `@media (max-width: 719.9px)` 블록이 `button`/`select`/
`input`에 이미 이 값을 전역으로 걸어 두었으니, 새 컨트롤을 만들 때 이 셀렉터 안에
잡히는 표준 엘리먼트라면 **따로 손댈 필요가 없다** — 커스텀 클릭 영역(`role="button"`
span 등)만 직접 `min-h-10` 또는 히트 영역 확장을 챙긴다.

- **서랍/시트**: 좌측 메뉴는 좁은 화면에서 본문을 덮는 서랍(`AppShell`이 처리),
  모달은 아래에서 올라오는 시트(`Modal`이 처리) — 새로 만들 필요 없음(5절).
- **목록성 표는 모바일 카드형, 시트성 표는 `.table-scroll`.** 기준: 한 줄이 독립된 개체를
  가리키고 행끼리 열을 비교할 필요가 없으면(회원 한 명, 사양서 한 건) **카드형** —
  `members.tsx`처럼 `<ol className="... pc:hidden">`(카드) + `<table className="... hidden pc:block">`
  (데스크톱 표)를 나란히 둔다. 반대로 행과 열이 같이 읽혀야 하는 매트릭스·필드 비교
  (권한 매트릭스, 버전 비교)는 `.table-scroll`로 표 자체를 가로로 흘린다:
  ```tsx
  <div className="table-scroll mt-3 rounded-xl border border-hairline">
    <table className="w-full min-w-[720px] border-collapse text-[13px]">...</table>
  </div>
  ```
  `.table-scroll`은 오른쪽에 열이 더 있다는 걸 가장자리 그림자로 말한다(`styles.css`) —
  `min-w-[...]`으로 표 실제 폭을 못박아야 그림자가 스크롤과 맞물린다.

## 7. ⚠ 넘침 방지

| 증상 | 원인 | 처방 |
|---|---|---|
| flex 줄 하나가 화면 폭을 뚫고 나간다(모바일에서 특히) | flex 자식은 기본 `min-width: auto` — 안에 표처럼 넓은 콘텐츠가 있으면 그 자식이 줄어들지 않고 부모(행)를 통째로 늘린다. 모바일 브라우저는 이걸 자동 축소해 "PC 화면처럼" 보여 주기까지 해서 `innerWidth` 기반 e2e 넘침 검사조차 못 잡는다 | 그 자식에 `min-w-0`을 준다 — `AppShell.tsx`의 본문 래퍼(`flex min-h-dvh min-w-0 flex-1 ... overflow-x-clip`)가 실제 처방례. 표를 감싸는 컨테이너에도 같이 준다 |
| 긴 이름·이메일이 옆 칸을 밀거나 줄바꿈으로 셀이 늘어진다 | "이름 칸"이 `min-w-0` + `truncate`(nowrap+overflow hidden+ellipsis 3종을 한 번에 줌) 세트를 안 갖춤 | 부모(flex 행)에 `min-w-0`, 이름 자신에 `block truncate` — `members.tsx` 표 행의 `<span className="min-w-0"><span className="block font-medium ...">{name}</span><span className="block truncate text-xs ...">{email}</span></span>`가 실제 사용례 |
| `flex-wrap` 제목 줄에서 버튼이 제목과 같이 눌린다 | 머리 블록에 `flex-wrap`이 없거나, 두 자식(제목 블록/버튼)의 `basis`가 정해지지 않아 좁은 화면에서 서로 밀어낸다 | 4절의 페이지 머리 블록 그대로 쓴다 — 제목 쪽엔 아무 `shrink` 지정 없이 자연폭, 버튼엔 필요시 `shrink-0` |
| 대시보드 미니 차트가 카드 안에서 한 조각만 찌그러져 보인다 | `viewBox`를 좁게(예: 110) 잡고 `preserveAspectRatio`가 기본(`meet`)이라 넓은 카드에서 중앙 부분만 확대돼 잘려 보인다(실기기에서만 눈에 띔) | 실제 비율에 가까운 넓은 `viewBox`(`charts.tsx`의 `Sparkline`은 `260×40`)로 그리고 `className="block h-auto w-full"`로 폭만 채운다 |
| 한/영 전환 시 버튼·라벨이 갑자기 넘친다 | 영문은 한글의 1.5~2배 길다 — 고정폭(`w-24` 등)에 라벨을 넣었기 때문 | 라벨 자리에 고정폭을 주지 않는다. 패딩 기반(`px-3` 등)으로 내용을 따라 늘어나게 두고, 칩·탭 줄은 `flex-wrap` |

공통 원인 하나: **flex 자식에 `min-w-0`이 없다.** 이 프로젝트에서 가장 자주 재발하는
넘침의 뿌리이므로, 새 컨테이너를 짤 때 "이 자식이 넓은 콘텐츠(표·긴 텍스트)를 담는가?"를
먼저 묻고, 그렇다면 `min-w-0`을 기본값으로 넣는다.

## 8. 글꼴

Pretendard Variable을 번들로 싣는다(`styles.css` 첫 줄 `@import "pretendard/dist/..."` —
외부 CDN 로드 아님). `font-sans`(기본 본문)와 `font-mono`(ID·버전·코드) 두 스케일뿐이다.

**`font-mono` 목록 끝에 한글 글꼴(Pretendard)을 반드시 붙인다.**
```
--font-mono: ui-monospace, 'Cascadia Mono', ..., 'Pretendard Variable', Pretendard, monospace;
```
이유: 글꼴 대체(fallback)는 **글자 하나 단위**로 일어난다. 한글이 없는 mono 목록이면
`SP-001 v2.3`처럼 ASCII만 있는 칸은 문제없지만, `산식`·`주기`처럼 **한글이 섞인 mono
칸**에서 그 한글 글자만 목록에 없어 브라우저 기본 글꼴(윈도 맑은 고딕 등)로 떨어져
나간다 — 한 줄 안에 두 글꼴이 섞여 보인다. 실제로 이 문제로 한 번 수정됐다
(`DESIGN.md` 2026-08-06 항목). 새 mono 사용처를 만들 때 이 토큰(`font-mono` 유틸)만
쓰면 자동으로 안전하고, 커스텀 `font-family`를 새로 적을 땐 이 규칙을 그대로 반복한다.

이름만 올린 글꼴은 없는 글꼴이다 — `font-family`에 새 글꼴을 추가하려면 반드시
번들(패키지 또는 self-host)로 같이 들여온다. 안 실으면 그 글꼴이 설치된 PC에서만
보이고 나머지는 대체 글꼴을 본다(Pretendard 자체가 이미 이 사고를 겪었다).

## 9. 상태·로딩 표현

관문은 `components/portal/Skeleton.tsx` 하나(규약 §3 이행).

| 컴포넌트 | 언제 | 모양 |
|---|---|---|
| `Skeleton` | 텍스트·숫자 한 칸이 곧 채워질 때 | 셔머(빛이 쓸고 지나감), 채워질 모양대로 `h-*`/`w-*` |
| `WidgetSkeleton` | 대시보드 위젯(카드) 전체가 로딩 | 안은 `Skeleton` 조합, **겉은 `.card-loading`**(테두리를 도는 빛) |
| `CtaButton` | 사용자가 방금 누른 상신·등록·요청 액션 | 누른 그 버튼에 스피너 + 잠금(`disabled`) + `busyLabel`("상신 중…") |

`.card-loading`(보더 빔)은 **"지금 일하는 중"인 카드 전용** — 로딩·실행 중에만 켠다.
장식으로 아무 카드에나 두면 "일하는 중" 신호가 죽는다(`Skeleton.tsx` 주석 그대로).
`CtaButton`은 `onAction`이 `Promise`를 반환하는 한 자동으로 눌린 채 잠기고 끝나면
풀린다 — 실제 요청이 없는 시연 화면은 `simulate()`로 지연만 흉내 낸다. 상신·등록·승인·배포
계열 버튼은 원시 `<button onClick>` 대신 전부 `CtaButton`으로 바꾼다.

선택 상태는 **면 + 글자 + ✓** 세 겹으로 말한다(규약 §16 — 색만으로 구분하면 색을 못
가르는 사람에게는 표시가 없는 것과 같다). `Chips.tsx`의 `ChipSelect`/`ChipMulti`가
`aria-pressed` + `bg-primary/15 text-primary` 면 + `✓ ` 접두 글자를 이미 갖췄다 —
새 선택 UI를 만들 때도 이 세 가지를 함께 준다(`AppShell.tsx`의 `Preferences` 세그먼트
버튼, `roles.tsx`의 액션 매트릭스 토글이 같은 패턴을 반복한다).

## 10. 모션

CSS `anim-*` 유틸(`styles.css`)은 **한 번 일어나고 끝나는 것** — 등장·퇴장·호버.
`motion`(구 framer-motion, 관문 `components/portal/motion.tsx`)은 **자리가 바뀌는 것**
(레이아웃 이동·목록 재정렬·드래그 후 미끄러짐)에만 쓴다. `motion`은 반드시
`import { m } from '#/components/portal/motion'`(관문)을 거친다 — `motion/react`를
화면에서 직접 import하지 않는다(번들 크기·`reducedMotion` 설정이 관문 한 곳에만 있다).

| 상황 | 쓰는 것 |
|---|---|
| 카드·타일 목록 진입 | `anim-fade-up` + `style={{ animationDelay: `${i*70}ms` }}` |
| 모달/드로어 열고 닫기 | `Modal`/`Drawer` 내부(이미 `m.div` 스프링 presence) — 화면에서 새로 안 만든다 |
| 위젯·행이 자리를 바꾼다(정렬 변경 등) | `motion`의 `layout` prop + 공통 `layoutSpring`(`motion.tsx`) |
| 섹션 펼침/접힘 | `.reveal-grid`(`grid-template-rows 0fr↔1fr`) — `roles.tsx`의 매트릭스 펼침이 실 사용례 |
| 버튼·칩 눌림 피드백 | `active:scale-95` |

**⚠ `layout`을 쓰는 요소에 `anim-fade-up`을 같이 얹지 않는다.** `anim-fade-up`은
`animation-fill-mode: both`로 `transform`을 등장 위치에 고정해 버려서, `motion`의
`layout` 이동(이것도 `transform` 기반)이 조용히 죽는다 — `.card-hover`에서 실측으로
잡힌 함정이다(`styles.css` 주석). 자리가 바뀌는 요소는 CSS 등장 애니메이션을 빼고
`motion`에만 맡긴다.

모든 등장 모션은 `prefers-reduced-motion: reduce`에서 꺼진다 — CSS는 전역 미디어
쿼리(`styles.css` 맨 아래)가, `motion`은 `MotionConfig reducedMotion="user"`가 처리한다.
새 애니메이션을 CSS로 직접 추가할 땐 이 전역 규칙에 걸리는 `animation`/`transition`
속성을 쓰면 자동으로 커버되니, `!important`로 뚫는 별도 처리를 하지 않는다.

## 11. 접근성 최소선

- 토글·선택 버튼에는 `aria-pressed`(`ChipSelect`/`Preferences` 세그먼트) 또는
  `aria-checked`(`Switch`, `role="switch"`)를 상태와 함께 준다.
- 아이콘만 있는 버튼(닫기 ×, 검색, 테마 토글 등)에는 반드시 `aria-label` — `Modal`/
  `Drawer`의 닫기 버튼, 헤더의 검색·테마·알림 버튼이 전부 이 패턴이다.
- `:hover`만 주고 `:focus-visible`을 안 주지 않는다 — 키보드 사용자에게는 아무 표시도
  없는 화면이 된다. 입력·버튼은 대부분 `focus:border-primary/60` 또는 브라우저 기본
  포커스 링을 살려 둔다.
- 덮은 것(Modal/Drawer/GNB 팝오버)은 전부 Esc로 닫힌다 — 새로 만들 덮개도 `keydown`
  리스너로 이 동작을 갖춘다(관문을 쓰면 이미 되어 있다).
- 열려 있는 동안 `body`+`html` 스크롤을 잠근다(`Modal`/`Drawer` 내부 구현 참조) — 스크롤바가
  `html`에 붙어 있어 `body`만 잠그면 트랙 폭만큼 레이아웃이 틀어진다.
- 색으로만 말하지 않는다 — 상태는 배지 안 글자와 함께, 선택은 `✓`와 함께(9절), 증감은
  화살표 아이콘과 숫자를 함께(`charts.tsx`의 `DeltaChip`).
- 다크 배경 위 텍스트는 `ink-muted` 이하를 본문에 쓰지 않는다(대비 확보, `DESIGN.md` Rules 3).
