## 1. 한 눈 지도

이 프로젝트는 **두 사업의 합본**이다 — 센터 KPI 품질(ICDAP)과 IBD 사양서 관리(IDMS).
하나의 저장소·인증·메뉴 프레임워크를 공유하고, **메뉴가 둘을 가른다**. 자세한 사업
맥락은 `docs/PROJECT_CONTEXT.md`.

```
Project/
├─ docs/                        ← 문서 정본 5종 (이 문서 포함)
├─ frontend/                    ← React 19 + TanStack Start/Router · Vite 8 · Tailwind v4
│  ├─ src/
│  │  ├─ routes/                ← 파일 기반 라우트. 22개 화면 + __root(셸) + index(리다이렉트)
│  │  │     ⚠ 전역 Provider(I18n·Toast)는 **__root 에만** 둔다 — AppShell 안에 두면
│  │  │       화면 컴포넌트가 Provider 위에 놓여 훅이 기본값을 집는다(§토스트 사고)
│  │  ├─ components/portal/     ← 공통 관문 15종 (§3) — 화면은 여기를 지나 그린다
│  │  ├─ data/                  ← 목데이터 정본(specs·roles·nav·dashboard 등) = 서버 폴백
│  │  ├─ lib/                   ← 관문(api.ts·i18n.tsx·accent.ts·i18n-dict-*.ts)
│  │  └─ styles.css             ← 토큰 원본(@theme) — 정본 설명은 DESIGN.md
│  ├─ e2e/mobile-smoke.spec.ts  ← Playwright, 393px, 29개 테스트
│  ├─ vite.config.ts
│  └─ DESIGN.md                 ← 시각 토큰 정본
├─ backend-python/               ← FastAPI — **공통 기능의 정본**
│  ├─ app/
│  │  ├─ main.py                 ← 라우터 등록 + db.init() + seeds.seed_if_empty()
│  │  ├─ db.py                   ← SQLite(data/app.db) — kv(JSON 통째) + 행 표
│  │  ├─ seeds.py                ← **시드 정본** (역할·메뉴·FAQ·회원·감사로그…)
│  │  └─ api/                    ← auth·me·rbac·community·directory·embeds·navs·hello
│  └─ tests/                     ← pytest, HMG_DB_PATH 로 DB 격리
└─ backend/                      ← Spring Boot 4.1 — **같은 API를 나란히 낸 후보**
   └─ src/main/
      ├─ java/.../api/           ← *Controller — FastAPI 와 같은 엔드포인트 모양
      ├─ java/.../store/JsonStore.java  ← kv+행 구조를 JdbcTemplate 로 그대로 옮김
      ├─ java/.../bootstrap/SeedRunner.java
      └─ resources/seed/*.json  ← backend-python 시드를 덤프해 옮긴 것(손 복사 금지)
```

### 프런트 · 백엔드 두 벌의 관계

**API 모양이 정본이다.** 어느 백엔드가 뒤에 있어도 프런트는 같은 엔드포인트를 부른다
(`/api/me`, `/api/me/menu`, `/api/notices` …). 백엔드 프레임워크가 미확정(`docs/PROJECT_CONTEXT.md`
§3·§7)이라 두 벌을 나란히 두고 비교하는 중이며, **시드는 파이썬 쪽(`backend-python/app/seeds.py`)이
정본이고 Spring 쪽(`backend/src/main/resources/seed/*.json`)은 그 덤프본**이다
(`backend/.../SeedRunner.java` 주석: "시드 원본은 FastAPI 벌의 seeds.py 가 정본"). 손으로
두 벌을 나란히 고치면 반드시 어긋난다 — 스키마를 바꿀 때는 파이썬을 먼저 고치고 JSON을
다시 뽑는다.

```
frontend/src/data/*.ts  ─┐  화면이 서버 없이도 도는 폴백(mock) — 서버가 없으면
   (프런트 자체 목데이터) │  조용히 이 값을 쓴다 (규약: 시연 안전)
                          │
   브라우저 ── lib/api.ts(관문) ── fetch('/api/...') ── vite proxy '/api' → :8080
                          │
              ┌───────────┴────────────┐
              ▼                        ▼
   backend-python :8080 (정본)   backend/ (Spring) :8081 (같은 API, 후보)
   app/seeds.py 가 시드 정본  ──▶ resources/seed/*.json (덤프본)
   SQLite data/app.db             H2(PG 호환) data/hmg 또는 실 PG(postgres 프로필)
```

백엔드 확정 시 진 쪽을 지우고 `CLAUDE.md`/CI를 갱신한다 — API 모양이 같으므로 프런트는
무변경이다(`docs/PROJECT_CONTEXT.md` 끝줄).

## 2. 띄우는 법

### 프런트 (포트 3000)

```bash
cd frontend
npm install
npm run dev            # http://localhost:3000
```

### FastAPI (포트 8080, 정본)

```bash
cd backend-python
python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"   # Windows. mac/Linux는 .venv/bin/pip
.venv/Scripts/uvicorn app.main:app --reload --port 8080
```

### Spring Boot (포트 8081, 후보)

```bash
cd backend
./gradlew bootRun      # 기본 프로필: H2(PostgreSQL 호환 모드), 파일 data/hmg
# 실 PostgreSQL 로 붙이려면: ./gradlew bootRun --args='--spring.profiles.active=postgres'
# (HMG_PG_URL / HMG_PG_USER / HMG_PG_PASSWORD 환경변수 필요)
```

### vite proxy — 어느 백엔드를 보고 있나

`frontend/vite.config.ts` 의 `server.proxy['/api']` 가 `http://localhost:8080` 로 **고정**되어
있다. 즉 **기본은 FastAPI(정본)를 본다.** Spring 벌을 켜서 비교하려면 이 값을 8081로
바꾼다(`docs/PROJECT_CONTEXT.md`: "프런트 전환 = vite proxy 대상만 8080↔8081"). 두 서버를
동시에 켜 두어도 프런트는 proxy 설정이 가리키는 쪽 하나만 본다.

### mock fallback — 서버 없이도 화면이 돈다

`frontend/src/lib/api.ts` 의 `useApi<T>(path, fallback)` 훅이 이 프로젝트의 시연 안전판이다:

```ts
export function useApi<T>(path: string, fallback: T): { data: T; live: boolean; reload: () => void }
```

- 마운트 시 `apiGet(path)` 를 한 번 부른다. 응답이 오면 `data` 를 그 값으로, `live = true`.
- 실패(네트워크 오류·서버 없음·4xx/5xx)하면 **조용히 `fallback`(= `frontend/src/data/*.ts`
  목데이터)에 머문다**, `live = false`.
- SSR·첫 렌더는 **항상 fallback** — 그래서 서버 응답이 늦게 와도 수화(hydration)
  불일치가 안 난다.

`apiGet`/`apiSend`/`apiPost` 세 함수가 갈리는 이유가 다르다:

| 함수 | 실패 시 | 쓰는 곳 |
|---|---|---|
| `apiGet<T>` | `null` (조용히) | `useApi` 의 내부 — 조회 폴백용 |
| `apiSend` | `boolean` | 저장류(즉시 반영, 실패해도 토스트만) |
| `apiPost<T>` | `{ok:false, detail: 사람 말}` | 로그인처럼 **그 자리에서** 실패 이유를 보여야 하는 곳(규약 §21 예외) |

⚠ 본개발에서는 이 관문을 규약 21절대로 바꾼다(연결 실패를 사람 말로, 401은 로그인으로) —
§9 참고.

## 4. 데이터 흐름 — 판단은 서버, 그리기는 화면

`docs/RBAC_설계노트.md` §2의 원칙("메뉴는 서버가 내려준다")이 이 코드베이스에서 실제로
어떻게 도는지:

```
                    역할 정본 (kv:"roles" — matrix + scope + features)
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        ▼                           ▼                           ▼
 GET /me/menu                GET /me/features            GET /me/abilities
```

## 5. 다국어 쓰는 법

관문은 `frontend/src/lib/i18n.tsx`. 사용은 어디서나 같다:

```tsx
const { locale, setLocale, t, tf } = useI18n()

t('common.save')                        // 사전에 있으면 그 언어, 없으면 key 그대로
t('gnb.myPage', '마이페이지')             // fallback 지정 — 사전에 없어도 화면이 안 깨짐
tf('gnb.notReady', { label: t('gnb.myPage') })   // 숫자·이름이 낀 문구는 파라미터로
```

- **사전은 화면 단위로 가른다.** `lib/i18n.tsx` 안의 `CORE_DICT` 에는 브랜드·`common.*`·
  LNB(`nav.*`)·GNB·로그인·대시보드 머리글만 두고, 나머지는
  `i18n-dict-work.ts`(사양서·승인·배포·검증)·`i18n-dict-admin.ts`·`i18n-dict-community.ts`·
  `i18n-dict-page.ts` 로 나눈다. `DICT = { ...CORE_DICT, ...WORK_DICT, ...ADMIN_DICT, ... }`
  로 합쳐지고, **키가 겹치면 뒤에 합쳐진 화면 사전이 이긴다.**
- **되풀이 낱말은 `common.*` 재사용.** '저장'·'취소'·'삭제' 같은 건 화면 사전에 새로
  만들지 않는다 — 새로 만들면 화면마다 다른 영어가 붙는다.
- **화면 제목은 `nav.<key>` 재사용.** `AppShell.tsx`의 헤더 breadcrumb 은
  `displayNav.flatMap(...).find(i => i.key === active)?.label` 로 LNB 라벨을 그대로
  되찾아 쓴다 — 화면이 자기 제목을 따로 번역하지 않는다.
- **EN 라벨의 우선순위**: 서버 `nav[].items[].labelEn`(관리자가 메뉴 관리에서 넣은 값,
  `PUT /api/nav/label`) → 사전(`nav.<key>`) → 한국어 원문. `AppShell.tsx`:
  ```ts
  label: locale === 'en' ? (it.labelEn ?? t(`nav.${it.key}`, it.label)) : it.label
  ```
- **필터 값은 키로 두고 표시만 번역한다.** 상태·카테고리 같은 내부 상태값을 라벨
  문자열로 저장하면 언어를 바꾸는 순간 그 값이 사전에 없는 문자열이 되어 필터가
  아무것도 못 찾는다(규약 §4 규칙 7 — 실제로 세 화면에서 고친 사고). 셀렉트·칩의
  `value` 는 항상 원래 키, 보이는 글자만 `t()` 를 거친다.
- **번역하지 않는 것**: 사용자가 입력한 값(사양서 제목·태그)과 감사 로그 문장 — 그때
  일어난 일의 기록이라 사전에 없다.

## 6. 코드 컨벤션

### import 순서

```
react/router 계열 → #/components/* → #/data/* → #/lib/*
```

`#/*` 는 `frontend/package.json` 의 `imports` 필드(`"#/*": "./src/*"`)가 뚫어 준
경로다 — 상대 경로(`../../lib/api`) 대신 항상 `#/lib/api` 로 쓴다. 이 순서는 **eslint
`import/order` 로 강제되어 있지 않다** — 사람이 지키는 관례다. 새 파일을 만들 때
이 순서를 따른다(예: `frontend/src/routes/dashboard.tsx` 상단 import 블록 참고).

### 네이밍

- 컴포넌트 파일: PascalCase (`Modal.tsx`, `AppShell.tsx`, `TableauEmbed.tsx`)
- 데이터·관문 파일: camelCase (`specs.ts`, `roleDefs`, `accent.ts`)
- 라우트 파일: TanStack Router 파일 기반 규칙을 그대로 따른다 — `specs.tsx` 가
  `/specs` 레이아웃, `specs_.$specId.tsx` 의 `_` 는 그 레이아웃을 벗어나 독립 라우트
  `/specs/$specId` 를 만든다는 뜻(TanStack Router "escape" 문법). 라우트를 추가하면
  `npm run generate-routes` 로 `routeTree.gen.ts` 를 다시 만든다 — **이 파일은 손으로
  고치지 않는다**(`CLAUDE.md`).

### 주석은 "왜"를 적는다

이 저장소의 실제 스타일 — 무엇을 바꿨는지가 아니라 **왜 이렇게 정했는지, 안 하면 무슨
일이 생기는지**를 적는다. 실제 예:

```ts
// frontend/src/lib/api.ts
/** 조회 훅 — 서버가 답하면 그 값, 아니면 mock(fallback).
 * SSR·첫 렌더는 항상 fallback 이라 수화 불일치가 없다. */
```

```ts
// frontend/vite.config.ts
// ⚠ @tanstack/devtools-vite 는 걷어냈다 — 클라이언트 콘솔을 서버로, 서버 로그를
// 다시 클라이언트로 되쏘는 로그 에코가 warn/error 하나를 무한 증폭해 dev 서버를
// 네 번 죽였다(2026-08-05 실사고 — 최악은 로그 파일 5.4GB).
```

`⚠` 는 **실제로 겪은 사고에만** 붙인다(`CLAUDE.md` 작업 규율 6항) — 남발하면 진짜
위험 신호가 묻힌다.

### 타입은 현실을 말한다

옵셔널 필드는 실제로 없을 수 있는 값에만 붙인다 — "일단 옵셔널로" 식으로 두지 않는다.
예 (`frontend/src/data/nav.ts`):

```ts
export interface NavItem {
  key: string
  label: string
  labelEn?: string   // 관리자가 안 넣었을 수 있다 — 없으면 사전이 채운다
  icon: IconName
  to?: string         // '시스템 알림'처럼 아직 라우트가 없는 항목도 있다
  badge?: number
}
```

### 색·치수는 토큰만

`frontend/DESIGN.md` 가 정본. `@theme` 에 없는 값이 필요해 보이면 단계가 틀린 것 —
새 값을 손으로 박지 않는다.

### 페이지 안에서 컴포넌트를 정의하지 않는다

라우트 컴포넌트 함수 **본문 안에서** 다른 컴포넌트를 `function Foo() {...}` 로 새로
선언하지 않는다 — 부모가 리렌더될 때마다 그 함수 참조가 바뀌어 자식이 매번
**새로 마운트**된다. 이 저장소는 `Drawer`/`Modal` 이 render-prop `close` 와 퇴장
애니메이션(`onAnimationComplete`)에 의존하므로, 그 안에 즉석 컴포넌트를 두면 애니메이션
상태가 리렌더마다 리셋된다. 화면 전용 하위 컴포넌트는 라우트 파일의 **모듈 최상위**에
두거나(`AppShell.tsx`의 `NavRow`, `Icon` 처럼) 별도 파일로 뺀다.

## 8. 함정 모음 — 이미 겪은 것

### 0. 터널 너머의 리뷰어는 **옛 화면**을 본다 (2026-08-11)
- **증상**: 리뷰어 화면에서 대시보드 KPI 위젯이 1열로 펴져 스파크라인이 카드 폭만큼
  부풀었다("위젯이 너무 크다"). **로컬은 멀쩡했다.**
- **원인**: Cloudflare 엣지가 `/src/styles.css` 같은 dev 자산을 확장자만 보고 캐시한다.
  브라우저는 **새 마크업 + 옛 CSS** 를 받는다 — 그날 새로 붙인 `@container`·`@sm:` 규칙이
  옛 CSS 에 없어서 컨테이너 쿼리가 통째로 죽어 있었다. 같은 서버인데 **경유지가 다르다**.
- **처방**: `vite.config.ts` 의 `server.headers` 에 `Cache-Control: no-store`(dev 전용).
  이미 캐시를 물고 있는 브라우저는 **한 번 강력 새로고침**(Ctrl+F5)이 필요하다.
- **교훈**: 로컬만 보고 "안 재현된다"고 답하지 말 것. 리뷰 경로(터널)로도 한 번 본다.

### 1. devtools 로그 에코가 dev 서버를 죽였다
- **증상**: `npm run dev` 서버가 반복해서 죽고, 로그 파일이 5.4GB까지 자랐다.
- **원인**: `@tanstack/devtools-vite` 가 클라이언트 콘솔을 서버로, 서버 로그를 다시
  클라이언트로 되쏘는데 이 왕복이 warn/error 하나를 무한 증폭시켰다. `enhancedLogs`
  옵션으로도 안 꺼졌다.
- **처방**: 플러그인 자체를 제거(`frontend/vite.config.ts`), 라우터 devtools 패널도
  `__root.tsx` 에서 함께 걷어냈다.

### 2. 모바일에서 `min-w-0` 이 없으면 컬럼째 늘어난다
- **증상**: 모바일 실기기에서 상세 화면이 "PC 축소판"처럼 1033px로 보였는데, e2e
  넘침 검사 21건이 전부 초록이었다.
- **원인**: flex 항목의 기본 `min-width: auto` 가 안쪽의 넓은 표를 따라 컬럼째
  늘어난다. 그러면 모바일 브라우저가 넘친 페이지를 축소해서 보여주고, `innerWidth`
  도 같이 커져 검사가 통과해 버린다.
- **처방**: `AppShell.tsx` 본문 컨테이너에 `min-w-0` + `overflow-x-clip` 이중 안전벨트.
  넘침 검사 기준 자체도 바꿔야 한다(다음 항목).

### 3. e2e 넘침 검사는 `innerWidth` 가 아니라 `viewportSize()` 로
- **증상**: 위 사고와 짝 — 검사가 스스로 속는다.
- **원인**: 넘친 페이지를 모바일 브라우저가 축소 표시하면서 `window.innerWidth`
  자체가 늘어나, "뷰포트만큼 넘쳤나"를 그 값과 비교하면 항상 통과한다.
- **처방**: 기준을 `page.viewportSize()`(장치 뷰포트 폭, 고정값) 하나로 — 실측 값과
  비교하지 브라우저가 보고하는 동적 값과 비교하지 않는다(`mobile-smoke.spec.ts`).

### 4. `flex-wrap` 줄에서 제목 블록은 `basis` 없이 짓눌린다
- **증상**: 좁은 화면에서 카드 제목이 한 글자씩 세로로 늘어섰다(실기기 실증).
- **원인**: `flex-wrap` 행 안의 제목 블록에 `flex-1` 만 주면 줄바꿈 대신 최소폭까지
  짓눌린다.
- **처방**: `min-w-0 flex-1 basis-64` 조합 — 기준 폭(`basis-64`)을 주면 좁으면 줄바꿈,
  기준 폭보다 넓으면 늘어나는 정상 동작이 된다. 목록 행 컴포넌트(검증엔진·검증
  리포트 등)에서 이 패턴을 쓴다.

### 5. 좁은 `viewBox` SVG는 넓은 카드에서 가운데로 쪼그라든다
- **증상**: "차트가 너무 작다"는 모바일 실기기 피드백.
- **원인**: `viewBox`를 좁게(예: 110) 잡으면 `preserveAspectRatio` 기본값(`meet`)이
  전체를 다 채우는 대신 비율을 지키며 가운데에 작게 그린다.
- **처방**: 넓은 비율(예: 260×40)로 그리고 `h-auto`+`w-full` 로 두면 카드 폭을 그대로
  채운다(`charts.tsx` 의 `Sparkline`).

### 6. `layout` 요소에 `anim-fade-up` 을 같이 얹으면 애니메이션이 조용히 죽는다
- **증상**: 위젯 재정렬 애니메이션이 실행되지 않는다(`.card-hover` 때 실증).
- **원인**: `anim-fade-up` 은 `fill: both` 로 `transform` 을 고정시킨다. motion 의
  `layout` 이동도 `transform` 기반이라 나중 걸린 값이 이겨 이동이 멈춘다.
- **처방**: 자리가 바뀌는 요소에는 CSS 등장 애니메이션(`anim-*`)을 겹쳐 걸지 않는다
  — 등장은 motion 쪽 초기 애니메이션(`initial`/`animate`)으로 처리한다
  (`frontend/DESIGN.md` 모션 시스템 절).

### 7. Spring Boot 4는 Jackson 패키지가 `tools.jackson` 이고, MockMvc는 `webmvc-test` 아티팩트
- **증상**: 익숙한 `com.fasterxml.jackson.*` import가 컴파일되지 않는다 /
  `@AutoConfigureMockMvc` 를 못 찾는다.
- **원인**: Boot 4가 Jackson 3로 올라가며 패키지명이 바뀌었고(`JsonStore.java` 상단
  주석), MockMvc 자동구성이 `spring-boot-starter-test` 에서 분리되어
  `spring-boot-starter-webmvc-test` 로 옮겨졌다(`build.gradle` 주석).
- **처방**: `import tools.jackson.core...` / `import
  org.springframework.boot.webmvc.test.autoconfigure.AutoConfigureMockMvc` 로 쓰고,
  `build.gradle` 에 `spring-boot-starter-webmvc-test` 를 별도로 추가한다. 테스트는
  `@ActiveProfiles("test")` 로 `application-test.yml`(H2 인메모리)을 타게 해 개발 DB
  파일과 분리한다.

### 8. pytest는 `HMG_DB_PATH` 로 DB를 격리하지 않으면 개발 DB를 오염시킨다
- **증상**: 개발 중 화면에 "테스트 공지"가 떴다.
- **원인**: `backend-python/app/db.py` 의 `DB_PATH` 는 모듈 import 시점에 한 번
  읽힌다. 테스트가 같은 `data/app.db` 파일에 쓰면 테스트 데이터가 개발 화면에 그대로
  보인다.
- **처방**: `tests/conftest.py` 가 `app` 을 import 하기 **전에**
  `os.environ["HMG_DB_PATH"]` 를 임시 파일 경로로 바꾼다(conftest가 가장 먼저 실행되는
  것을 이용). Spring 벌도 같은 이유로 `application-test.yml` 에서 H2 인메모리를 쓴다.

### 9. `nav`·`nav_requires` 는 "비어 있을 때만 채우기" 예외 — 항상 덮는다
- **증상**: 메뉴 구조를 코드에서 바꿨는데 기존 DB가 옛 메뉴를 계속 냈다.
- **원인**: 시드의 기본 규칙은 "비어 있을 때만 채운다"(회사가 화면에서 조정한 값을
  재기동이 되돌리면 안 되므로 — `RBAC_설계노트.md` §4). 하지만 `nav`/`nav_requires`
  는 **화면에서 고치는 값이 아니라 코드가 정본**이라 이 규칙을 적용하면 구조 변경이
  기존 DB에 반영되지 않는다.
- **처방**: `seeds.py`의 `seed_if_empty()` 와 `SeedRunner.java` 양쪽 모두 `nav`/
  `nav_requires` 두 키만 예외로 두어 **매번 UPDATE-or-INSERT** 로 덮는다. 관리자가
  메뉴 관리 화면에서 고친 `labelEn` 같은 값은 이 두 키가 아니라 `nav` 안의 항목별
  필드라 재기동 때 통째로 날아간다(프로토타입 한정 — §9 참고).

### 10. 고정폭 글꼴 목록 끝에 한글 글꼴이 없으면 한글만 딴 글꼴로 떨어진다
- **증상**: 산식·주기처럼 한글이 섞인 모노스페이스 칸에서 한글 부분만 다른 서체로
  보인다.
- **원인**: 글꼴 대체는 **글자 하나 단위**로 일어난다. `--font-mono` 목록에 한글을
  지원하는 글꼴이 없으면, 그 글자만 브라우저가 다음 폴백(윈도 기본 글꼴)으로 넘어간다.
- **처방**: `--font-mono` 목록 **끝에 Pretendard 를 추가**한다 — ASCII는 앞쪽 고정폭
  글꼴로, 한글만 자연스럽게 본문 글꼴을 이어받는다(`frontend/DESIGN.md` 테마 시스템
  절, 2026-08-06 수정).

## 9. 본개발 이관 목록

프로토타입이라 약식으로 둔 지점들 — 요구사항이 확정되면 아래 표의 "교체 지점"을
고친다. **소프트 게이트**가 공통 전제다: 지금은 인증·SSO·JWT·결재가 미확정이라
"거절"보다 "약식으로 통과시키고 표시만 한다" 쪽을 택했다.

|---|---|---|---|
| 토큰 인증 | `uuid4` 세션 토큰을 서버 kv에 저장, `Authorization: Bearer <token>` | `backend-python/app/api/auth.py`(`issue_token`), `lib/api.ts`(`getToken`/`setToken`) | JWT Access/Refresh 정책 확정 후 표준 발급·재발급 흐름으로 교체 |
